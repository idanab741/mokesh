# ארכיטקטורה

## עקרון מנחה: Local-first
כל כתיבה נעשית קודם ל-SQLite במכשיר ורק אחר כך מסתנכרנת. לכן התיעוד מיידי, עובד בלי רשת,
והודעת "נשמר" מוצגת רק אחרי שהשורה באמת נכתבה מקומית.

```
מסך (src/app)  →  hooks (TanStack Query)  →  repository  →  SqlDriver  →  SQLite
                         │                                         ▲
                         └── לאחר כתיבה: invalidate + requestSync ──┘
                                                 │
                                    SyncEngine ⇄ RemoteGateway ⇄ Supabase (Postgres + RLS)
```

## שכבות
| שכבה | תיקייה | תלויה ב | הערות |
|---|---|---|---|
| ממשק | `src/app`, `src/components` | hooks, domain, design | אין SQL ואין Supabase במסכים |
| לוגיקה עסקית | `src/domain` | – | פונקציות טהורות, נבדקות ב-Jest. אימות עם zod |
| גישה לנתונים | `src/data` | domain | repositories מעל ממשק `SqlDriver` |
| סנכרון | `src/data/sync` | data | מנוע מול ממשק `RemoteGateway` (Supabase או fake בבדיקות) |
| שירותים | `src/services` | – | Supabase client, config, secure storage |

## החלטות טכנולוגיות (וסטיות מהבריף)
- **Expo SDK 58, Expo Router, TypeScript strict, TanStack Query, Zustand, Supabase** – לפי הבריף.
- **SQLite בכל הפלטפורמות דרך `SqlDriver`**: `expo-sqlite` ב-native, `sql.js` ב-web ובבדיקות.
  אותו SQL רץ בכל מקום, ולכן ה-repositories נבדקים מול SQLite אמיתי בלי סימולטור.
- **גרפים: רכיבים עצמיים מעל `react-native-svg`** במקום ספריית גרפים. סיבה: שליטה מלאה ב-RTL,
  בנגישות ובעיצוב, בלי תלות ב-Skia. ציר הזמן משמאל לימין, כמו בעקומות גדילה מודפסות.
- **בחירת תאריך ושעה: רכיב עצמי** (מדרג ימים + שדות ספרות) שמתנהג זהה ב-iOS, Android ו-web ונוח ביד אחת.
- **אייקונים: lucide** + שני אייקונים שצוירו באותו סגנון (בקבוק, חיתול) כי אינם קיימים בסט.

## מודל הפעילויות
טבלה אחת `activity_events` עם `activity_type` ו-`payload` (JSON) מאומת:
- בלקוח: סכמות zod ב-`src/domain/activity.ts` (`validateDraft`).
- בשרת: `is_valid_activity_payload()` כ-CHECK constraint.
הוספת סוג פעילות = סכמה + טופס + תווית, בלי שינוי מבני.

טיימרים (שינה, הנקה) מחושבים תמיד מחותמות זמן שמורות. סגירת האפליקציה לא משפיעה על המשך.
שינה שחוצה חצות נחתכת לפי ימים בסיכומים ובסטטיסטיקות ומופיעה ביומן של שני הימים.

## סנכרון והתנגשויות
- לכל שורה מקומית `sync_status` (`pending` / `synced` / `conflict`) ו-`version` (גרסת השרת האחרונה שנראתה).
  הדגל `pending` הוא התור: שורד סגירת אפליקציה, ואין תור נפרד שיכול ללכת לאיבוד.
- **Push**: שורה חדשה נכנסת ב-insert-if-absent לפי `id` (ולכן ניסיון חוזר לא יוצר כפילות).
  שורה קיימת מתעדכנת רק אם השרת עדיין בגרסה שהמכשיר ראה (`WHERE version = ?`).
- **Pull**: לפי `updated_at` מאז הסמן האחרון, כולל מחיקות רכות. אף פעם לא דורס עריכה מקומית ממתינה.
- **מדיניות התנגשות**: אם שני הצדדים שינו ותוכן שונה, שום דבר לא נדרס. השורה מסומנת `conflict`,
  העריכה המקומית נשמרת, עותק השרת נשמר לצדה, וההורה בוחר במסך הרשומה איזו גרסה להשאיר.
  עריכות זהות ומחיקה כפולה מתיישבות בשקט. מחיקה מול עריכה היא התנגשות (לא מוחקים עריכה של מישהו אחר).
- טריגרים לסנכרון: אחרי כתיבה (debounce), חזרה לחזית, חזרת רשת, כניסה לחשבון, וכפתור ידני.

## אבטחה ופרטיות
- הרשאות נאכפות ב-Postgres (RLS + טריגרים + RPC), לא בממשק. ראו DATABASE.md.
- רק מפתח publishable בצד לקוח. Session נשמר ב-Keychain/Keystore (`expo-secure-store`).
- ייצוא נתונים (JSON) ומחיקה מלאה זמינים ממסך "הילד שלי".
- אין אנליטיקה, אין פרסום, אין צד שלישי שמקבל נתוני ילדים.

## נגישות ו-RTL
- RTL כפוי (config plugin + `I18nManager`), סגנונות לוגיים בלבד (`start`/`end`).
- טווחי שעות ותאריכים עטופים ב-LTR isolate כדי שלא יתהפכו בתוך טקסט עברי.
- לכל כפתור אייקון יש `accessibilityLabel`, יעדי מגע 44–48, ניגודיות טקסט AA (ראו הערות ב-`tokens.ts`),
  תמיכה בהגדלת טקסט עד 150%.

## הכנה ל-AI (שלב שני)
`computeRangeStats` ו-`summarizeDay` מחזירים מבנים מדודים בלבד (כולל "ימים עם תיעוד"), שהם הקלט הטבעי
למנוע תובנות. טבלת `consents` כבר כוללת `ai_processing`. אין צ'אט ואין קריאות למודל בגרסה הזו.
